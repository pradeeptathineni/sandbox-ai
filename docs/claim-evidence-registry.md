# Claim-to-evidence registry audit

`python -m harness.claim_evidence_registry` is a stateless JSON stdin/stdout API with closed `register`, `revise`, and `audit` operations. It calculates a canonical claim revision digest over the claim ID, integer revision, exact text, and subject project/revision. Evidence locators use existing Experiment Evidence journal UUIDs and packet digests; packet bytes are checked by the existing native Sandbox packet validators for trial-pair, paired-comparison, and retrieval-experiment evidence. SB08 reviewer links are checked against the retained blind-session/review identities and exact source packet binding.

The native module stores nothing. `register` returns the exact registry object plus its first audit; callers retain that output in their chosen record store. `audit` is the cold-read/revalidate operation: supply the exact registry object, current claim revision, fresh packet snapshots and optional SB08 snapshots. `revise` makes the caller provide evidence and review references again; it never copies prior review/session IDs into the new claim revision. A revised claim must advance the same claim ID by one and change text or subject basis. An audit against a changed claim returns `stale-claim-revision` with `proofInherited: false`. Missing records, failed/partial packet outcomes, native validation errors, unknown source revisions, and missing reviews remain distinct statuses. `currentSubjectRevision` is caller-supplied; Sandbox does not fetch or independently verify the current project revision.

Statuses describe exact identity, packet completion, and link availability. They do not establish that a claim is true, that a reviewer is independent or accurate, or that a release is approved. Reviewer names remain unauthenticated metadata; public export remains outside this API. All fixtures are synthetic. The registry's `completed` status means the native packet reports completed/comparable selected evidence; it does not assert that the evidence supports the registered claim.

Focused check: `python -B -m unittest discover -s tests -p 'test_claim_evidence_registry.py' -v`.
